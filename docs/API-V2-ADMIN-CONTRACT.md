# v2 administrator bootstrap and recent authentication

App v2.0.0 preserves /api/v1. Compatible OpenAPI contract 1.5.0 adds GET /admin/access before the new frontend consumes it.

GET /api/v1/admin/access accepts no query/body filters. Verified, enabled Google identity plus current global facilitator role is required. Scoped API tokens, captains, learners and anonymous clients are denied. Response: {administrator:true, capabilities:["workshops","learners","certificates","requests","integrations","delivery"], recentAuthMaxAgeSeconds:300}. No staff directory, learner profile, email or institutional data is returned. Check current authority on each call; audit access through existing canonical API-read audit. Standard no-store, request ID, bounded rate/errors: 400 unknown filters, 401 missing/revoked/disabled identity, 403 insufficient authority/API token, 429 throttle, 500 safe internal failure.

Sensitive Google-admin operations require server-verified auth_time within the existing token-creation recency policy: 300 seconds, allowing the existing 60-second future clock tolerance. Reuse this policy; it is not an invented admin idle/session timeout. Validate at trusted transport boundaries before dispatch; domain services continue to enforce current role/resource/privacy transactionally. Missing/old auth_time returns failed-precondition with safe reauthentication guidance. Bootstrap and ordinary reads do not require a new popup. API-token automation retains its existing scopes/authority and is not forced through browser reauthentication.

Coverage: global facilitator participant sync/attendance/close/publication/revoke/certificate corrections, learner profile/completion/request/removal administration; certificate reconciliation and REST administrator mutations; API credential creation/revocation; outbox redrive; non-owner administrator PDF export/preview. Learner self-service/PDFs and captain-region authority remain unchanged. Mandatory MFA is not enabled, no new roles/accounts/cookies are created.

The browser checks token recency and offers Google reauthentication before sending these operations. This is UX only: bypassing the browser must still fail on the server. A rejected step-up must not commit or audit a successful mutation. Cancelled popup/account switch clears the pending action and returns an actionable error. Do not automatically repeat a write after an uncertain response; existing idempotency receipts remain authoritative.

Required tests: anonymous/student/captain/scoped-token denial; valid Google administrator bootstrap with no learner writes; current role revocation; missing/old/future auth_time versus accepted fresh time; tokens never acquire Google-only privileges; cancellation/account switch; separate admin initialization and session behavior; no profile action or learner history subscription from administrator startup. Existing callable contracts remain supported and are updated to enforce the same recent-auth policy for Google administrators.

Admin browser persistence: owner approved current-tab/session persistence on 28 October 2026. Use Firebase browserSessionPersistence for the separately named admin app; no new idle timeout or cookie session layer. Refresh retains that tab's session; closing it clears the admin session. Learner Firebase persistence and shared Auth UIDs are unchanged.

All authenticated callables additionally verify current token revocation/disabled-account state using the same checkRevoked policy as REST; Firebase callable signature verification alone is insufficient. Transport UID/verified token must match, provider details remain private, and no caller-supplied auth_time is accepted.
