# Delivery lifecycle observability

Current source extension: [2.2.1 contract, coverage and recovery](OBSERVABILITY-2.2.1.md). This supersedes the older review-snapshot and source-job test-ingestion descriptions below.

Service inspiredlearning-delivery is distinct from inspiredlearning-api. Source owns .github/workflows/observability.yml and scripts/observability. No observer is active until the owner securely binds DYNATRACE_CI_TOKEN and enables DYNATRACE_CI_ENABLED=true. On 30 October the owner added DYNATRACE_CI_TOKEN under the existing Production environment; names-only API inspection confirmed it exists. The observer references that environment with deployment:false and retains the unset/off enable flag. No token value was read or copied from Firebase/chat.

The after-completion observer checks out the repository's trusted default branch, never a PR head or executable artifact. contents/actions/issues/pull-requests permissions are read-only; there is no deploy/OIDC/write grant or shared untrusted cache. Same-repository Checks runs are read back from the GitHub API and validated against repository/run/attempt/revision/workflow identity. Fork runs are excluded. Bounded jobs/steps preserve real success/failure/skipped/cancelled status. Span timestamps come from GitHub, not fabricated request parents; skipped/missing timestamps do not become duration spans. Native OTLP traces/logs/delta metrics use the CI service and approved tenant. Metric dimensions are bounded phase/outcome, not IDs.

Issue and PR transitions use trusted-source lifecycle metadata, stable event IDs and allowlisted fields; titles, bodies, command text, logs and emails are excluded. Published release tag resolution and package version must match before release metadata is reported. A release event is not a deployment marker. Review submissions/dismissals are observed directly; review edits remain outside the event subscription. No broad PR log capture or PR artifact execution/parsing is enabled. Trusted main test artifacts are parsed only as bounded data by the independent observer.

Runner-owned structured test summaries contain counts/status/duration only. Node reporting uses the final cumulative test:summary, avoiding double-counted file summaries. Playwright reports final expected/unexpected/flaky/skipped/interrupted/missing results. Missing/partial/cancelled reports never establish success. Reports upload with if:always and 14-day retention. Per-suite test-event ingest is restricted to trusted main push execution; PR jobs receive no ingest credential and their untrusted reports are not consumed by the privileged observer. GitHub-confirmed workflow/job/step facts remain distinct from CI-reported test summaries.

Credentials are secret references only. The CI token needs approved BizEvents and OTLP ingest permissions; runtime Secret Manager binding is not reused automatically. Reporter failures are visible separately from the source run/deployment and can be retried with stable IDs. Source API facts and CI test-event providers are not canonical learner business events. Native workflow/job/step traces and count/duration metrics do not manufacture RUM/runtime parentage; revision joins are metadata correlation.

Local unit/collector tests check passed/failed/skipped/cancelled/missing/partial summaries, source/attempt mismatch, stable IDs, release/tag/deployment mismatch and actual separate OTLP signal payloads with the CI service resource. They do not prove tenant visibility, repository secret configuration, real observer execution, alert routing or production deployment correlation. Verify those after approved secure binding; preserve source failures and report only the successful ingest stage actually observed.

The source run is read through its attempt-specific GitHub endpoint, so delayed completion events cannot accidentally describe a newer rerun. The observer accepted count describes BizEvent HTTP 202 responses only. Native marker acceptance is checked separately by the deployment replay tool. SDK shutdown completion does not certify OTLP per-record acceptance; inspect each signal response/partial rejection and tenant data separately before enabling production reporting.
